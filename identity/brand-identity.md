# metapatrol — brand identity v3.1

All assets referenced here are generated by `@metapatrol/brand-kit` (`packages/brand-kit/`) into `@metapatrol/brand` (`packages/brand/`); paths below are relative to that package. The brand as a browsable site is `apps/preview` (`npm run build -w @metapatrol/preview`, static output in `apps/preview/dist/preview/browser`). Earlier versions (the v1 icon, the v3 drafts) are in the repository's Git history.

## 1. brand idea

`metapatrol` is an independent engineering label for infrastructure, developer tools, AI systems and autonomous software.

The identity should feel like it belongs to a technical lab rather than a SaaS company: precise, modular, system-oriented, understated and recognisable. AI is part of the engineering stack, not the visual gimmick.

Core idea:

> systems for a more autonomous world.

Primary scope:

`infrastructure / developer tools / autonomous systems`

## 2. brand character

metapatrol is:

- lowercase by design
- technical without looking like generic cyber security
- modern without chasing AI visual clichés
- modular and composable rather than monolithic
- independent, pragmatic and engineering-led
- comfortable with complexity, but visually disciplined

The brand should communicate that metapatrol builds real systems: runtimes, gateways, operators, registries, automation, agent infrastructure and small focused tools.

## 3. naming

The brand name is always written as:

`metapatrol`

Avoid `MetaPatrol`, `METAPATROL` and other casing in normal brand usage.

For projects, use the brand as a namespace rather than giving every repository its own separate visual identity:

- `metapatrol / mcp-gateway`
- `metapatrol / tool-gate`
- `metapatrol / oci-registry`
- `metapatrol / forgejo-github-bridge`

The individual project name remains the technical identifier. The metapatrol mark acts as the common engineering label.

### brand levels

How much of the brand a project carries depends on what it is, not on how much
someone likes it. Each level includes the one before.

| level | for | carries |
|---|---|---|
| **0 — repository** | libraries, operators, small tools | `metapatrol.json`, README header with the project lockup `[mark] metapatrol / <name>`, the social preview, the README structure from section 10 — all from `npx @metapatrol/brand-kit init` |
| **1 — tool with a UI** | consoles, dashboards, docs sites | the project's favicon set (the metapatrol mark), `@metapatrol/style`, the namespace `metapatrol / <name>` in the UI header (`mp-namespace`) |
| **2 — product with its own icon** | something listed where a namespace cannot appear: an app store, a marketplace, a desktop dock | a product icon derived from the mark's lattice (same hexagon, same gap, no new colours), decided case by case |

Level 2 is the exception and needs a reason. A project that only wants to look
distinct is level 0 or 1: the name, set in JetBrains Mono next to the mark, is
what distinguishes it.

The project lockup sets `metapatrol /` in Inter Medium (secondary text colour) and
the project name in JetBrains Mono (primary text colour), as the `mp-namespace`
pattern does in interfaces.

## 4. brand mark

The v3 mark is a modular, geometric systems glyph built from several independent structural segments around an inner active element.

The mark is intentionally abstract. It should evoke:

- infrastructure
- modular systems
- control planes
- computation
- autonomous software
- engineered components

It should **not** be interpreted as a literal cloud, Git graph, Kubernetes reference, shield, cube, radar symbol or AI sparkle.

The cyan inner panel is the active signal. The graphite outer structure is the system around it.

### construction

The mark is constructed, not drawn (`construction/construction.svg`):

- a regular pointy-top hexagon on an isometric lattice, 20 lattice steps per half width
- every edge is vertical or at ±30°
- one gap width everywhere: one lattice step
- the signal panel is an isometric square with half the hexagon's edge length
- the top edge of the drop block and the top edge of the signal panel lie on one line
- flat fills only, corner radius 6 at a 1024 canvas

Changes to the mark are made in `packages/brand-kit/src/geometry.ts`, never by editing the SVGs.

### optical sizes

| rendered size | file | construction |
|---|---|---|
| 48 px and larger | `mark/metapatrol-mark-*.svg` | primary |
| 20–40 px | `mark/metapatrol-mark-small-*.svg` | coarser lattice, no channel, no drop block |
| 16 px | `mark/metapatrol-mark-favicon-*.svg` | small construction with widened gaps |

Each exists in the colourways `dark`, `light`, `mono-white` and `mono-black`.

### clear space

`x` = the vertical edge of the signal panel = ¼ of the mark height. Keep at least `1x` free around the mark and around every lockup (`construction/clearspace.svg`).

### usage

Use the mark on its own for:

- GitHub organisation avatars
- favicons
- application icons
- CLI / terminal branding
- repository badges
- package and container metadata

Use the mark with the `metapatrol` wordmark where brand recognition matters more than compactness.

Do not distort, rotate, add extra effects or introduce additional brand colours into the mark.

## 5. visual language

The visual system is dark, restrained and technical.

Preferred motifs:

- grid systems
- precise alignment
- thin structural dividers
- technical metadata
- monospace labels
- modular panels
- small status indicators
- generous negative space around the primary mark

The visual identity may borrow from instrument panels, terminals, infrastructure consoles and engineering diagrams, but should avoid retro-futurism or cyberpunk decoration.

## 6. colour system

The source of truth for every colour is the token set in `tokens/` (repository
root); `tokens/contrast.json` holds the contrast rules both themes must meet and
CI checks them. The lists below describe the brand; the tables under *themes*
are what applications use.

### primary

- **signal cyan** — `#00E5FF`
  - active elements
  - links
  - focus states
  - important status accents
  - the signal element inside the brand mark

- **background** — `#050607`
  - primary dark background

- **surface** — `#0F1419`
  - cards, panels and elevated UI surfaces

- **graphite** — `#171D25`
  - mark structure on light backgrounds
  - structural elements

- **steel** — `#5B6776`
  - mark structure on dark backgrounds
  - 3.5:1 on background, 3.2:1 on surface (graphite would be 1.2:1 and effectively invisible)

- **muted** — `#25303A`
  - dividers, secondary elements and inactive states

- **text primary** — `#E6EDF3`
  - headings and primary text

- **text secondary** — `#9AA7B4`
  - labels, metadata and supporting text

### semantic UI colours

These belong to product interfaces, not to the core logo:

- success — `#22C55E`
- warning — `#F59E0B`
- error — `#EF4444`
- info — `#3B82F6`

The brand itself should remain overwhelmingly graphite, black, off-white and cyan.

### themes

Dark is the brand's home; light exists for applications and documentation.
Applications use these semantic roles, never the raw values.

| role | dark | light | use |
|---|---|---|---|
| `bg` | `#050607` | `#FFFFFF` | page background |
| `surface` | `#0F1419` | `#F4F6F8` | cards, panels |
| `surface-2` | `#171D25` | `#E6EDF3` | raised or hovered surface |
| `line` | `#25303A` | `#D5DBE1` | dividers, decorative borders |
| `line-strong` | `#5B6776` | `#748291` | borders of inputs and controls |
| `fg` | `#E6EDF3` | `#171D25` | primary text |
| `fg-muted` | `#9AA7B4` | `#4A5563` | secondary text, labels, metadata |
| `fg-subtle` | `#7A8896` | `#5F6B78` | placeholders, disabled, supporting text; at least 4.5:1 on every surface, as it is mostly small |
| `signal` | `#00E5FF` | `#00E5FF` | signal as fill: active state, selection |
| `signal-fg` | `#00E5FF` | `#00707F` (petrol) | signal as text or line: links, focus rings |
| `on-signal` | `#050607` | `#050607` | text on a signal fill |
| `signal-wash` | cyan 10 % | cyan 14 % | selected rows and items |
| `success` | `#22C55E` | `#15803D` | |
| `warning` | `#F59E0B` | `#B45309` | |
| `error` | `#EF4444` | `#B91C1C` | |
| `info` | `#3B82F6` | `#1D4ED8` | informational notices, never links |
| `mark.structure` | `#5B6776` | `#171D25` | the mark's structure |

### colour rules

- The mark uses exactly two colours: structure (steel on dark, graphite on light) and signal cyan. No gradients, no glow.
- Links and focus states use `signal-fg`: cyan on dark, petrol on light. Info blue is for informational notices only, never for links.
- On light backgrounds cyan is 1.5:1 against white. Use it only as a fill (buttons, chips, selection, the mark's panel) with `on-signal` text or next to graphite, never as text or thin lines on white. Petrol `#00707F` is the signal colour for text on light.
- Status colours differ per theme: the light theme uses darker values so that status text stays readable.
- Mono variants (`mono-white`, `mono-black`) are for single-colour contexts: print, embossing, overlays on photos.

## 7. typography

### primary UI and web

**Inter**

Use for:

- website copy
- navigation
- UI
- documentation headings
- product interfaces

Preferred weights: Regular, Medium, Semibold and Bold.

### technical typography

**JetBrains Mono**

Use for:

- code
- CLI examples
- repository identifiers
- metadata
- technical labels
- small section headings where a systems / instrument-panel feel is appropriate

A form field's label is not one of them: it names a thing for whoever fills the
form, so it is set in Inter, as written (`mp-field-label`). The section label
(`mp-label`, "01  DEPLOYMENT") stays mono capitals: it is structure.

The contrast between Inter and JetBrains Mono is part of the identity: human-readable interface plus machine-readable system layer.

## 8. wordmark

The wordmark is simple lowercase `metapatrol` typography: **Inter Medium, tracking −0.015em**, converted to outlines (`wordmark/`).

It should not attempt to visually compete with the symbol. The mark provides recognition; the wordmark provides clarity.

Lockups (`lockup/`, each in all four colourways):

- **horizontal** — `[mark] metapatrol`; the preferred lockup. Wordmark size = 0.5 × mark height, gap between mark and wordmark = `1x`, the wordmark's ascender-to-baseline box is centred on the mark.
- **stacked** — mark above the wordmark, gap `1x`.
- **descriptor** — horizontal lockup with `infrastructure / developer tools / autonomous systems` in JetBrains Mono beneath, spanning the full lockup width.

The descriptor is functional, not a slogan. Do not re-set the wordmark in live text next to the mark; use the lockup files.

## 9. voice and language

metapatrol communicates like good technical documentation.

The tone is:

- concise
- precise
- calm
- technically confident
- slightly opinionated when there is an engineering reason
- free of hype

Prefer:

> small, composable infrastructure tools.

over:

> revolutionary AI-powered cloud-native solutions.

Avoid exaggerated claims, generic startup language and unnecessary references to AI. If AI is relevant, describe what the system actually does.

## 10. content and open-source presentation

A repository published under metapatrol should feel deliberate, however quickly it was built.

Each public project should ideally have:

- a clear one-sentence purpose
- concise architecture / design rationale
- explicit scope and non-goals
- repeatable build and test instructions
- license and contribution information
- the shared metapatrol visual language where useful

The goal is not to make every tool look like a product launch. The goal is to make the collection look like the output of one coherent engineering practice.

## 11. design principles

When deciding whether something fits the identity, use these principles:

**engineered over decorative**  
Every visual element should feel intentional and structural.

**systems over products**  
metapatrol represents a body of engineering work, not a collection of unrelated SaaS brands.

**signal over spectacle**  
Cyan is an active-state accent, not neon decoration.

**modular over monolithic**  
The identity should reflect composability and independent components.

**lowercase always**  
The understated typography is part of the character of the brand.

## 12. compact identity definition

> **metapatrol** is an independent engineering label for infrastructure, developer tools and autonomous systems.
>
> Visually it is dark, modular, precise and restrained. Graphite structures form the system; cyan marks the active signal. The brand uses lowercase typography, Inter for interfaces and JetBrains Mono for the technical layer.
>
> It should feel like an engineering lab — not a SaaS startup, not an AI brand and not a generic cloud-native vendor.

## 13. assets

| directory | contents |
|---|---|
| `mark/` | mark in three optical sizes × four colourways |
| `wordmark/` | wordmark as outlines, four colourways |
| `lockup/` | horizontal, stacked and descriptor lockups, four colourways |
| `app/` | app icon (SVG, PNG 1024/512/192/180), org avatar in `light` (white background, graphite mark; the one to use on GitHub, reads in both GitHub themes) and `dark` (SVG, PNG 1024/512/256), `favicon.svg` (switches with the browser's colour scheme), `favicon.ico` (16/32/48) |
| `construction/` | construction grids and clear-space diagram |

Every SVG has a PNG with the same name next to it (transparent background) for places that do not accept SVG, such as GitHub. Widths: marks 1024, small 64, favicon 32, wordmarks and horizontal lockups 2000, stacked lockups 1200. For a README that follows GitHub's light/dark theme, use `<picture>` with a `(prefers-color-scheme: dark)` source for the `-dark` file and the `-light` file as the fallback.

Rebuild everything with:

```
npm ci
npm run build
```

`@metapatrol/brand-kit` renders PNG and ICO itself; no Inkscape or ImageMagick is needed. The fonts in `packages/brand-kit/fonts/` are licensed under the SIL Open Font License.
